Fenote Raey Academy is not starting from a blank drawing. MaJo Bridge Technology and Events PLC already operates MaJo e-School Bridge as a multi-school cloud system. Fenote Raey is the next school on MaJo e-School Bridge, with its own name, logo, classes, and module mix.

8. Customization: adapt existing modules and add new ones

This is the section Fenote Raey asked us to state clearly. The platform is not a locked foreign template. Customization happens on three layers, so the Academy is never told “wait for a new product.”

8.1 Layer 1 — Module pack (what exists for this school)

From the platform owner console (MaJo Bridge, PIN-protected — not the school admin), each of the 59 desks has an on/off switch for Fenote Raey. Dashboard, profile, settings, and logout stay on so people can still sign in.

  • All on — Fenote Raey receives the full catalogue. New desks we ship later stay on.
  • A chosen subset — for example year-one academics, students, messages, and finance only. Transport and inventory wait. Those desks are hidden from everyone at Fenote Raey, including the school admin.
  • Turning a module on later is a switch, not a data migration. The student record is already there.

This is how a school already runs a dense academic pack on the same platform (Lebawi International School), while Fenote Raey chooses its own mix. The same company already ships other products — GYMOS, Tena, printing systems, and websites — so adding a Fenote-specific desk is a known path, not a new vendor.

8.3 Layer 3 — Ability to adapt new modules

When Fenote Raey grows a new office, we do not start a second school system. The rule is:

  1. Reuse the student (and staff) identity. A new desk reads the same SIS. No second “Fenote student id.”
  2. Attach to an existing family where we can (for example a new exam report still writes the markbook).
  3. Give it a sidebar id and a role allocation so only the right Fenote titles see it.
  4. Put it on the module pack. Fenote Raey can leave it off until the office is ready.
  5. Keep one cloud tenant. Parents still open the same login. They simply gain a new tile if that module is on and they are allowed to see it.

Examples of new-module paths we already used on this platform (so Fenote Raey can trust the pattern):

  • Exam bank pushing into the existing markbook instead of a parallel grade file.
  • LMS hub assembling lesson plans, homework, materials, and exams that already existed.
  • Admin CCTV as a staff desk over cameras the school already owned.
  • Go-live / privacy / MFA as a compliance desk on the same school record.
  • Per-school module toggles so a new desk can ship “off” until Fenote asks for it.

If Fenote Raey later needs a desk that is not in Section 7, MaJo Bridge writes a short change order, builds it on the live stores, and trains the named office. That is how the catalogue grew past 55 desks at Lebawi International School without splitting the school into a second product.

9. Roles, isolation, and day-to-day use

9.1 How a Fenote morning feels

Morning

Homeroom takes attendance. Absent and late parents can be notified. Directors see the same register — not a paper copy.

Teaching

The teacher opens LMS for that class: today’s plan, homework, materials, or an exam. Discussion stays in the class thread.

Marking

Scores go into the weighted markbook. Leadership approves. Only then do parents see the mark.

Gate and bus

The same student QR can mark class attendance and bus board/discharge. Parents see the bus as live only while the driver shares GPS.

Friday

IT / Administration Staff open Go-live, write the school snapshot, and walk a short digital-ops checklist. MaJo support joins if the whole school cannot log in.

9.2 Who sees what

  • A Grade 4 teacher sees her classes. She does not open safeguarding or the whole finance ledger.
  • The Principal / VP sees dashboards, grade approvals, reports, and overdue QA items.
  • Registrar owns the student register, admissions, and parent-link queue.
  • A parent sees only approved children, and only published grades.
  • A student sees own work. Never another child’s mark, never a draft.
  • A driver sees the assigned bus and passengers only.

Fenote Raey data is not visible to Lebawi International School or any other school tenant. Cross-school access is prohibited.

9.3 Security in school language

  • Least privilege. If a desk is off in the pack, or the role does not include it, the sidebar hides it.
  • Encryption. HTTPS in transit; hosted database and storage encryption at rest.
  • MFA. Opt-in authenticator for leadership and finance. The Academy chooses who must use it.
  • Backups. In-app school snapshot plus platform backup. Friday reminder when the last snapshot is older than 24 hours. Also keep a JSON copy on a school PC if Fenote policy requires it.
  • Audit. Leadership and QA can open who changed what.
