What to do next: LIA physical server + new cloud VM

Lebawi International Academy · MaJo e-School Bridge (MayaBela)

Version 1.0 · 10 November 2026, East Africa Time (Africa/Nairobi) · For an engineer who has never done this before. Written so you can sit in front of a keyboard and paste.

Golden rule — read twice. Never type the shared MaJo address https://hwkiihonthueadbhcvfi.supabase.co into either LIA machine, the LIA website build, or the LIA Android APK. Never run deploy-cloudflare-pages.cmd for this job. Fnote and other schools stay on https://mayabela.pages.dev. LIA gets its own empty database on the school’s physical server.
Option A in one sentence. The Lebawi physical server holds the only write database (teachers, marks, health). The new cloud VM is the public door (parents on mobile data) plus a disaster-recovery copy. The school router does not open ports to the internet. The campus starts an encrypted tunnel out to the cloud.

8. Phase 4 — WireGuard tunnel (cloud is the hub, campus dials out)

This is the encrypted pipe in the architecture drawing. The campus starts it. The school does not port-forward 443.

8.1 On CLOUD — make keys

sudo mkdir -p /etc/wireguard
cd /etc/wireguard
umask 077
wg genkey | tee server_private.key | wg pubkey > server_public.key
wg genkey | tee campus_private.key | wg pubkey > campus_public.key
sudo cat server_private.key; echo; sudo cat server_public.key; echo
sudo cat campus_private.key; echo; sudo cat campus_public.key

Four strings. Label them on paper: CloudPriv, CloudPub, CampusPriv, CampusPub.

sudo nano /etc/wireguard/wg0.conf

Paste this. Put the real keys and the cloud public IP.

[Interface]
Address = 10.66.0.1/24
ListenPort = 51820
PrivateKey = PASTE_CloudPriv
# NAT so campus can be reached as 10.66.0.2
PostUp = iptables -A FORWARD -i wg0 -j ACCEPT; iptables -t nat -A POSTROUTING -o $(ip -4 route get 1.1.1.1 | awk '{print $5; exit}') -j MASQUERADE
PostDown = iptables -D FORWARD -i wg0 -j ACCEPT; iptables -t nat -D POSTROUTING -o $(ip -4 route get 1.1.1.1 | awk '{print $5; exit}') -j MASQUERADE

[Peer]
# campus
PublicKey = PASTE_CampusPub
AllowedIPs = 10.66.0.2/32
echo "net.ipv4.ip_forward=1" | sudo tee /etc/sysctl.d/99-wireguard.conf
sudo sysctl --system
sudo systemctl enable --now wg-quick@wg0
sudo wg show

You want wg0 listening on 51820. The peer will show “latest handshake” after campus connects.

8.2 On CAMPUS — dial out

sudo nano /etc/wireguard/wg0.conf
[Interface]
Address = 10.66.0.2/24
PrivateKey = PASTE_CampusPriv

[Peer]
PublicKey = PASTE_CloudPub
Endpoint = CLOUD_PUBLIC_IP:51820
AllowedIPs = 10.66.0.1/32
PersistentKeepalive = 25
sudo systemctl enable --now wg-quick@wg0
ping -c 3 10.66.0.1
sudo wg show

You want replies from 10.66.0.1 and a handshake a few seconds old. If ping fails: cloud UDP 51820, keys swapped wrong, or campus outbound UDP blocked — ask LIA IT to allow UDP 51820 to the cloud IP.

8.3 Publish campus Kong only on the tunnel

On CAMPUS after Docker/Kong is running (next phase). For now create the helper so it is ready:

sudo nano /etc/systemd/system/lia-wg-kong.service
[Unit]
Description=Expose campus Kong to WireGuard only
After=docker.service wg-quick@wg0.service
Wants=wg-quick@wg0.service

[Service]
ExecStart=/usr/bin/socat TCP-LISTEN:8000,bind=10.66.0.2,fork,reuseaddr TCP:127.0.0.1:8000
Restart=always

[Install]
WantedBy=multi-user.target

Do not start this service until Kong answers on campus localhost (Phase 5). Then:

sudo systemctl enable --now lia-wg-kong.service

15. Phase 11 — Nightly backup on campus + copy to cloud (the replica)

Week-1 replica for beginners: a daily file copy, not a live read database. All parent traffic still goes through the tunnel to campus. If campus dies, you restore this file onto a spare — you do not fail over onto MaJo shared cloud.

On CAMPUS:

sudo nano /usr/local/bin/lia-backup.sh
#!/bin/bash
set -euo pipefail
STAMP=$(date +%F)
DIR=/opt/lia/backups/$STAMP
mkdir -p "$DIR" /opt/lia/backups/latest
cd /opt/lia/supabase/docker
docker compose exec -T db pg_dump -U postgres postgres | gzip > "$DIR/postgres.sql.gz"
cp -f "$DIR/postgres.sql.gz" /opt/lia/backups/latest/postgres.sql.gz
find /opt/lia/backups -mindepth 1 -maxdepth 1 -type d -mtime +14 -exec rm -rf {} \;
sudo chmod +x /usr/local/bin/lia-backup.sh
sudo crontab -e

Add:

15 2 * * * /usr/local/bin/lia-backup.sh
40 2 * * * scp /opt/lia/backups/latest/postgres.sql.gz cloudadmin@10.66.0.1:/opt/lia/replica/postgres.sql.gz

On CLOUD first:

sudo mkdir -p /opt/lia/replica
sudo chown cloudadmin:cloudadmin /opt/lia/replica

You need SSH from campus → cloud over WireGuard (key login, no password). Test once by running the backup script by hand. Copy the same file to a USB the principal keeps in another building every week. Restore once to a throwaway folder before you leave — a backup never restored is not a backup.

Streaming Postgres replica (hot standby on the cloud) is the “advanced” Option A. Do it after week 1 if LIA wants faster failover. Until then the dump file is the replica. Live reads and writes stay on campus.

18. If something breaks — first three checks

  1. CAMPUS docker compose ps — all running?
  2. CAMPUS sudo wg show — handshake fresh? If not: sudo systemctl restart wg-quick@wg0
  3. CLOUD curl -I http://10.66.0.2:8000/auth/v1/health — if this fails, parents will fail even if the padlock looks fine.

There is no automatic fallback onto www.majobridge.com. That would copy children’s records onto the shared tenant. Restore from last night’s dump instead.
