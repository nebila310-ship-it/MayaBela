5.3 Make an SSH key on your Windows laptop (first time only)

Open PowerShell. Paste. Press Enter through the questions (blank passphrase is OK for a commissioning laptop that stays with you).

ssh-keygen -t ed25519 -C "lia-cloud"
type $env:USERPROFILE\.ssh\id_ed25519.pub

A line starting ssh-ed25519 AAAA… appears. Copy the whole line. In the VM dashboard, field “SSH keys” / “authorized keys”, paste it. Create the VM. Copy the public IPv4 onto paper as CLOUD_PUBLIC_IP.

If the panel only offers a root password. Log in once as root, create cloudadmin, add your key, then disable password SSH later. Do not keep typing the root password from an internet café.

5.4 Prove you can enter the VM

From the laptop, not on school Wi-Fi (use phone hotspot if you are in the school). Replace the IP and user:

ping CLOUD_PUBLIC_IP
ssh cloudadmin@CLOUD_PUBLIC_IP

First time, it asks “Are you sure you want to continue connecting?” Type yes. You want a prompt like cloudadmin@something:~$.

Success. Ping may work or be blocked (some providers drop ping — that is OK). SSH must work. You can type uname -a and see the word Ubuntu.
If SSH fails. Wrong user (try ubuntu or root). Key not in the panel — recreate or paste again. Provider firewall: allow TCP 22 from your current public IP. Laptop has no OpenSSH: Windows Settings → Optional features → OpenSSH Client. “Permission denied (publickey)”: you are offering a different key than the panel has — run ssh -v cloudadmin@CLOUD_PUBLIC_IP and read “Offering public key”.

No website, no padlock, no database, no school data. You only have a locked empty Linux box on the internet. Next: point the domain at this IP.

SSH in. Replace nothing except if the user is not cloudadmin.

sudo apt update

If it asks to restart services, press Enter to accept the default. If it says “A new version of /etc/ssh/sshd_config is available”, keep the local version (the default highlighted).

7.3 Paste — firewall

Only four holes to the internet: SSH (22), HTTP (80, only so Certbot can prove you own the name), HTTPS (443, the real door), WireGuard (51820/udp, the tunnel).

sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 51820/udp
sudo ufw enable
sudo ufw status

When it asks “Proceed with operation (y|n)?” type y. You want Status: active, and those four rules. Do not allow 5432, 8000, or 54323 on the cloud.

7.4 Paste — placeholder website

sudo mkdir -p /var/www/lia-erp
echo "LIA ERP cloud door — waiting for files" | sudo tee /var/www/lia-erp/index.html
sudo rm -f /etc/nginx/sites-enabled/default

The default nginx page would confuse Certbot later. You will drop a real nginx config in Phase 6. For now the folder exists.

Success. sudo ufw status lists 22, 80, 443, 51820. ls /var/www/lia-erp shows index.html. wg command exists (wg --help prints text).
If apt fails. Clock wrong: timedatectl. DNS on the VM: ping -c 2 archive.ubuntu.com. Disk full: df -h. If ufw enable drops your SSH session, the panel “console” (VNC) is how you log in without SSH and run sudo ufw allow OpenSSH again.

8.2 Write the LAN address (do this first)

ip a
hostname -I

Find the line that looks like inet 192.168.1.50/24 (not 127.0.0.1, not a docker or wg0 address). That number is CAMPUS_LAN_IP. Write it on the paper. Ask LIA IT to make a DHCP reservation on the school router so this number never changes after a reboot.

8.3 Paste — updates and tools

sudo apt update
sudo apt -y upgrade
sudo apt -y install ca-certificates curl git ufw nginx unzip jq wireguard socat

socat is a small pipe. Later it will take “something arrived on the tunnel IP port 8000” and hand it to Kong on localhost. The cloud needs that because it cannot see 127.0.0.1 on campus.

Campus firewall is stricter. Do not run sudo ufw allow 80/tcp to the whole world on this box. Staff use the LAN. Parents use the cloud door.

8.4 Paste — campus firewall

sudo ufw allow OpenSSH
sudo ufw allow from 192.168.0.0/16 to any port 80
sudo ufw allow from 192.168.0.0/16 to any port 443
sudo ufw allow 51820/udp
sudo ufw enable
sudo ufw status

If hostname -I showed 10.something, use this instead of the 192.168 lines:

sudo ufw allow from 10.0.0.0/8 to any port 80
sudo ufw allow from 10.0.0.0/8 to any port 443

8.5 Docker on campus (the database will live here)

Docker is a way to run Postgres + Auth + Storage as ready-made boxes so you do not install each by hand. Paste the whole block.

sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update
sudo apt -y install docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo usermod -aG docker $USER

Log out of the SSH session and log in again (or reboot). Until you do that, Docker still asks for sudo. Then:

docker --version
docker compose version
docker ps
Success. Version numbers print. docker ps prints a header (CONTAINER ID …) and an empty list. CAMPUS_LAN_IP is on paper. Firewall does not list 80/443 from Anywhere.
If Docker says permission denied. You skipped logout/login. If apt cannot see Docker’s repo, the server has no internet — plug WAN or set DNS 1.1.1.1 in netplan with LIA IT. If RAM is 4 GB, later docker compose up will freeze — add RAM or stop other software.

9. Phase 4 — WireGuard tunnel (cloud is the hub, campus dials out)

In one sentence. You create a private cable that only these two computers can use, with addresses 10.66.0.1 (cloud) and 10.66.0.2 (campus). The campus starts the call. The school router does not port-forward 443.
WhoOur sideMachineCLOUD first, then CAMPUS
Time30–45 minutesDepends onPhases 2 and 3 (wireguard package + UDP 51820)

9.1 Why campus dials out

Most school routers block inbound connections. Outbound UDP is usually allowed (same idea as a phone calling out). Cloud listens on 51820. Campus keeps the session alive every 25 seconds (PersistentKeepalive) so the school NAT does not forget the mapping. Private keys never leave the machine that made them. You only copy public keys on paper.

9.2 On CLOUD — make this machine’s keys

sudo mkdir -p /etc/wireguard
cd /etc/wireguard
sudo umask 077
wg genkey | sudo tee server_private.key | wg pubkey | sudo tee server_public.key
sudo cat server_private.key; echo
sudo cat server_public.key; echo

On paper write:

  • CloudPriv — stays on the cloud. Do not put this in chat or WhatsApp.
  • CloudPub — you will paste this on campus as the peer public key.
sudo nano /etc/wireguard/wg0.conf

Paste this. Replace only PASTE_CloudPriv and later PASTE_CampusPub (you will get CampusPub from the next subsection — you can save with a dummy and edit again, or do 9.3 first and come back).

[Interface]
Address = 10.66.0.1/24
ListenPort = 51820
PrivateKey = PASTE_CloudPriv
PostUp = iptables -A FORWARD -i wg0 -j ACCEPT; iptables -t nat -A POSTROUTING -o $(ip -4 route get 1.1.1.1 | awk '{print $5; exit}') -j MASQUERADE
PostDown = iptables -D FORWARD -i wg0 -j ACCEPT; iptables -t nat -D POSTROUTING -o $(ip -4 route get 1.1.1.1 | awk '{print $5; exit}') -j MASQUERADE

[Peer]
# campus
PublicKey = PASTE_CampusPub
AllowedIPs = 10.66.0.2/32
echo "net.ipv4.ip_forward=1" | sudo tee /etc/sysctl.d/99-wireguard.conf
sudo sysctl --system
sudo systemctl enable --now wg-quick@wg0
sudo wg show

You want interface wg0, listening port 51820, and one peer. “latest handshake” stays empty until campus connects. If wg-quick fails, you still have PASTE_CampusPub as the dummy — finish 9.3, edit the file, then sudo systemctl restart wg-quick@wg0.

9.3 On CAMPUS — make this machine’s keys and dial out

sudo mkdir -p /etc/wireguard
cd /etc/wireguard
sudo umask 077
wg genkey | sudo tee campus_private.key | wg pubkey | sudo tee campus_public.key
sudo cat campus_private.key; echo
sudo cat campus_public.key; echo

Write CampusPriv (stays here) and CampusPub (paste into cloud wg0.conf Peer PublicKey, then restart cloud WireGuard). Then on campus:

sudo nano /etc/wireguard/wg0.conf
[Interface]
Address = 10.66.0.2/24
PrivateKey = PASTE_CampusPriv

[Peer]
PublicKey = PASTE_CloudPub
Endpoint = CLOUD_PUBLIC_IP:51820
AllowedIPs = 10.66.0.1/32
PersistentKeepalive = 25
sudo systemctl enable --now wg-quick@wg0
ping -c 3 10.66.0.1
sudo wg show

On cloud also run ping -c 3 10.66.0.2 and sudo wg show.

Success. Three ping replies each way. Both wg show lines say a handshake of a few seconds. Transfer: campus 10.66.0.2, cloud 10.66.0.1.
If ping fails. Keys swapped (private where public should be). Cloud UDP 51820 not open (Phase 2). Campus outbound UDP blocked — LIA IT must allow UDP 51820 to CLOUD_PUBLIC_IP. Wrong Endpoint (must be public IPv4, not 10.66). After editing conf: sudo systemctl restart wg-quick@wg0 on that machine. sudo wg-quick down wg0 then up if systemd is confused.

9.4 Prepare the Kong pipe (do not start it yet)

On CAMPUS create the helper so Phase 5 can turn it on after Kong exists:

sudo nano /etc/systemd/system/lia-wg-kong.service
[Unit]
Description=Expose campus Kong to WireGuard only
After=docker.service wg-quick@wg0.service
Wants=wg-quick@wg0.service

[Service]
ExecStart=/usr/bin/socat TCP-LISTEN:8000,bind=10.66.0.2,fork,reuseaddr TCP:127.0.0.1:8000
Restart=always

[Install]
WantedBy=multi-user.target

Save and quit. Do not run systemctl enable --now until Phase 5 health-check on localhost works. If you start it now, it will run but have nothing to talk to.

11. Phase 6 — Public padlock on the CLOUD VM

In one sentence. Nginx on the cloud becomes the public HTTPS door: files for erp, and a reverse-proxy for api that walks the tunnel to campus Kong. Let’s Encrypt then gives you the closed padlock.
WhoOur sideMachineCLOUD
Time20–40 minutesDepends onPhase 1 DNS grey, Phase 2 ports 80/443, Phase 5 curl from cloud to 10.66.0.2:8000

11.1 Why nginx is two server blocks

First block: a parent asks for the website — serve files from /var/www/lia-erp. Second block: the app asks for the API — do not serve files; proxy_pass to campus through the tunnel. If you point both names at files, login will fail. If you point both at Kong, the login page will be JSON.

11.2 Paste the nginx site

sudo nano /etc/nginx/sites-available/lia-erp

Paste the whole block. Change only the two hostnames if your paper uses different names.

server {
    listen 80;
    server_name erp.yourdomain.com;
    root /var/www/lia-erp;
    index index.html;
    location / {
        try_files $uri $uri/ /index.html;
    }
}

server {
    listen 80;
    server_name api.yourdomain.com;
    client_max_body_size 50M;
    location / {
        proxy_pass http://10.66.0.2:8000;
        proxy_http_version 1.1;
        proxy_connect_timeout 5s;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
sudo ln -sf /etc/nginx/sites-available/lia-erp /etc/nginx/sites-enabled/lia-erp
sudo nginx -t
sudo systemctl reload nginx

nginx -t must say “syntax is ok” and “test is successful”. Then from the laptop:

curl -sS -I http://erp.yourdomain.com
curl -sS -I http://api.yourdomain.com/auth/v1/health

ERP should be HTTP 200 with the placeholder. API should look like the Kong health you already saw (headers, not connection refused).

16.3 Backup script on campus

sudo nano /usr/local/bin/lia-backup.sh
#!/bin/bash
set -euo pipefail
export TZ=Africa/Nairobi
STAMP=$(date +%F)
DIR=/opt/lia/backups/$STAMP
mkdir -p "$DIR" /opt/lia/backups/latest
cd /opt/lia/supabase/docker
docker compose exec -T db pg_dump -U postgres postgres | gzip > "$DIR/postgres.sql.gz"
cp -f "$DIR/postgres.sql.gz" /opt/lia/backups/latest/postgres.sql.gz
find /opt/lia/backups -mindepth 1 -maxdepth 1 -type d -mtime +14 -exec rm -rf {} \;
sudo chmod +x /usr/local/bin/lia-backup.sh
sudo mkdir -p /opt/lia/backups
sudo chown -R liaadmin:liaadmin /opt/lia/backups
/usr/local/bin/lia-backup.sh
ls -lh /opt/lia/backups/latest/postgres.sql.gz

You want a file larger than a few kilobytes (empty schema is still hundreds of KB after MayaBela migrations). Then the nightly copy:

sudo crontab -e

If it asks for an editor, choose nano. Add these two lines (times are 02:15 and 02:40 Africa/Nairobi if the server timezone is set; the script itself exports TZ for the folder name):

15 2 * * * /usr/local/bin/lia-backup.sh
40 2 * * * scp /opt/lia/backups/latest/postgres.sql.gz cloudadmin@10.66.0.1:/opt/lia/replica/postgres.sql.gz

Run the scp once by hand now. On cloud: ls -lh /opt/lia/replica/postgres.sql.gz.

16.4 USB and a restore drill (do not skip)

Every week copy /opt/lia/backups/latest/postgres.sql.gz to a USB the principal keeps in another building. A backup never restored is not a backup. On a throwaway folder / spare VM with Docker, practice:

gunzip -c postgres.sql.gz | docker compose exec -T db psql -U postgres -d postgres

Do not run that restore against the live campus db unless you are in a real disaster and the principal has said so in writing.

Streaming Postgres replica (hot standby on the cloud) is the “advanced” Option A. Do it after week 1 if LIA wants faster failover. Until then the dump file is the replica. Live reads and writes stay on campus.
