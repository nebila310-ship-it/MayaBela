1. Persistence schema

School data is not one table per module. It is a document store:

public.app_documents (
  collection  text,     -- e.g. student_registry, grade_reports, fees
  school_id   text,     -- tenant; compared upper-case to jwt_school_id()
  doc_id      text,     -- row id inside the school
  data        jsonb,    -- payload
  primary key (collection, school_id, doc_id)
)

RLS is enabled. Anon has no policy on this table. Authenticated access is school-scoped and then role-scoped. Writes that use the Edge service role bypass RLS; those paths must call guardRegistryRecord (or an equivalent desk check) first.

3. Authorisation algorithms

3.1 SELECT path

authenticated request
  → policy app_documents_select_school
       school_id = jwt_school_id()
       AND app_doc_readable(collection, doc_id, school_id, data)
  → if jwt_role() = 'driver':
       AND app_doc_driver_may_read(...)   -- own bus only for children / GPS

Source: 20261109120000_insa_driver_need_to_know.sql (SELECT policy) plus app_doc_readable overlays. Driver function returns true immediately for non-drivers so teacher/admin/parent paths are unchanged.

3.2 Teacher write gate (SEC-001)

app_doc_teacher_may_write in 20261105120000_insa_permission_hardening.sql runs module gates before any see-all shortcut:

  • Always deny: school_registry, platform_audit_log.
  • Safeguarding: student_affairs / VP / principal / full_access only; else false.
  • Health / counselling / IEP / medication: student-affairs style roles or manage_students.
  • Payroll / HR collections: denied to ordinary classroom teachers.
  • Fees: paid-status fields require finance/cashier permission.
  • Homework / attendance / grades: assigned class (and see-all only after these gates).

A 403 from RLS must not trigger a full-school client snapshot (test/stale_write_storm_test.dart).

3.3 DELETE

Delete policy requires the same school match plus readability / teacher-write where the migration states it. Parents, students, and drivers are not on the teacher delete path.

3.4 Service-role registry writes

school-upsert-registry uses the service role after JWT verify. SQL write-guard does not run. Substitute: guardRegistryRecord in registry_write_policy.ts.

admission_applicationsmayWriteAdmissions → manage_students (registrar desk)

4. Driver need-to-know (LLD)

app_doc_driver_bus_id() looks up driver_registry in the JWT school by linked driver id, driverId, or loginUsername, and returns busId.

app_doc_driver_may_read for role driver:

  • student_registry: allow iff student’s transportId equals that bus. Walkers and other buses: deny.
  • bus_live_positions / scans / passenger status: own bus / own driver id.
  • Notices / conversations / bus catalogue: school-scoped only (no extra child dump).

Write trigger: driver may stamp own id on own-bus GPS/scans; foreign-bus overwrite refused. CAAT: 11_insa_driver_need_to_know.sql (9/9).

7. Client technical constraints

  • Connect only to configured SUPABASE_URL over HTTPS. Empty GitHub secrets must not dart-define blank URL/key (that wipes compiled defaults and breaks Admin login on Pages).
  • Pages headers: HSTS, CSP, X-Frame-Options: DENY, nosniff (web/_headers).
  • Privileged MFA prompt: GoLiveService.isPrivilegedMfaRole — roleAdmin or StaffRoles.accountant (includes titled finance copies). Teachers/principals remain opt-in.
